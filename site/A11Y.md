## 2. Serious and critical violations (fix before release)

### 2.1 Night theme: `--crit` red text is 3.85:1 on the card surface (WCAG 1.4.3). 22 nodes

Night `--crit` is `#d03b3b` (css/tokens.css, carried over from main's app.css). It is fine as a dot or stroke colour. As **text** on `--surface` `#0e1320` it gives 3.85:1, which is under the 4.5:1 needed for body text. (`.as-verdict b` is 18 px bold, just under the 14 pt bold large-text cut-off.) The Day value `#b91c1c` passes.

| Selector (axe target) | Owning file | Rule that sets the colour | Where |
|---|---|---|---|
| `.as-verdict > b` ("spreads") | js/fig_assess.js · css/p-assess.css | `.as-verdict[data-code="0"] b{color:var(--crit)}` (line 52) | assess / night |
| `.as-out` ("Outside: extrapolated") | js/fig_assess.js · css/p-assess.css | `.as-out{color:var(--crit)}` (line 56) | assess / night |
| `div[data-line="flex"\|"m7"\|"verdict"\|"risk"] > .gap.resp-flag[data-gap="true"] > b` ("Gap:"), 4 nodes | js/fig_response.js · css/fx-response.css | `.resp-flag.gap b{color:var(--crit)}` (line 23) | respond / night |
| `.mc-checks li[data-state="fail"] > .fail.status` ("Fail"), 16 nodes | js/fig_modelcards.js · css/p-models.css | `.mc-checks li[data-state="fail"] .status{color:var(--crit)}` (line 46) | models / night |

These uses of `var(--crit)` as a text colour were not flagged in this run, because the state did not occur, but they have the same problem: `.resp-level[data-level=High]` (css/fx-response.css line 42) and `#view[data-page="respond"] .fr-gap b` (css/p-respond.css line 10).

**Proposed fix (one token, then four one-word edits):**
- P1-A (css/tokens.css) adds a text-only token `--crit-ink`: Day `#b91c1c` (the current value), Night `#ef6464`. The Night value gives 5.89:1 on `#0e1320`, 6.29:1 on `#070a12` and 5.51:1 on `#141a2b`, computed with the WCAG formula.
- `--crit` itself stays as main had it, so chart and dot colours do not change.
- The owners of the CSS lines above switch `color:var(--crit)` to `color:var(--crit-ink)`.

The value `#ef6464` is a proposed colour, not a data number. The lead or the human may pick any value that passes 4.5:1.

### 2.2 Tables that arrive after the render pass are not keyboard-scrollable (WCAG 2.1.1). 2 nodes

| Selector | Owning file | Where |
|---|---|---|
| `.numbers > .scroll` (a "Show the numbers" table on an Assess figure) | js/charts.js `numbers()` | assess / day and night |
| `.as-curve > .scroll` (the growth-curve table) | js/fig_assess.js, via js/lib.js `table()` | assess / day and night |

`passes.js` a11y (pass 8) gives every `.scroll` `tabindex=0`, `role=region` and an `aria-label`, but only once, at render. Assess fills its cards after the growth run (`setBody`), so its tables miss the pass. A wide table then cannot be scrolled sideways without a mouse.

**Proposed fix:** `numbers()` in js/charts.js (P1-B) and `table()` in js/lib.js (P1-A) set `tabindex="0"`, `role="region"` and an `aria-label` on their own `.scroll` wrapper when they create it. The pass can stay as it is; it already keeps an existing `aria-label`. This covers every late table on the site, including tables that do not overflow at 1280 px and so were not flagged.

## 4. Remaining issues (not serious or critical)

### 4.1 Glossary terms have no focus outline (WCAG 2.4.7: weak indicator). Owner: P1-A, css/components.css

`.term{all:unset}` removes the outline. `.term:focus-visible` only changes the background to `--oxy-soft` and makes the dotted underline solid, which is easy to miss.

The sweep counted 61 such stops on 11 routes, as distinct stops per route:
- Model cards 25, Checks 10, NASA experiments 6;
- On Earth 4, Bench rig 4;
- Home 3, Put it out 3;
- Find it 2, Assess 2, Predict it 2.

**Proposed fix:** add `outline:3px solid var(--oxy);outline-offset:2px;border-radius:3px` to `.term:focus-visible` (components.css line 163), matching the site-wide `:focus-visible` ring in base.css line 16.

### 4.2 The dock is the last stop on the page (WCAG 2.4.3 is met; this is a usability note). Owner: P1-A, js/prefs.js

The dock is appended to `<body>`, so a keyboard user reaches "Read your way" after the whole page: 59 Tabs on Home, and more on long pages. Shift+Tab from the top reaches it at once, but few people know that. A possible change is a "Read your way" link next to the skip link. It is not required by the spec, so it is left for the lead to decide.

## 5. Not covered by these tools (check by hand)

- **A screen-reader pass with NVDA (Windows) or VoiceOver (macOS/iOS).** It should cover:
  - the order of headings and landmarks;
  - that chart `aria-label`s and tooltips are read;
  - that `#live` speaks once per verdict or risk change on Assess, and is not repeated while a slider is held down;
  - the dock dialog;
  - the More menu;
  - folds.
- **Contrast at A+ and A++ text sizes.** Not scanned separately. Bigger text only relaxes the WCAG thresholds, so the default size (scanned here) is the strictest case. The three sizes are still worth one look in the P7-B screenshots.
- **Contrast of text drawn inside SVG charts and on canvases.** axe does not measure canvas pixels and is unreliable on SVG `<text>`. The Design kit contrast table covers the chart tokens.
- **axe "needs review" (incomplete) results** are not collected. These are mostly text over gradients or images, such as the page-head banners and the hero.
- **Mobile widths.** All scans ran at 1280 px. The 320 px and 200 % zoom checks belong to P7-B (site/tools/shots.mjs). The mobile "Menu" button was not exercised by keyboard.
- **Real fonts.** Google Fonts were blocked. The real fonts render at the same CSS size and colour, so the contrast ratios do not change.
